# User stories

Short, concrete scenarios that pressure-test the app's usability. Each file
is one person, one moment, one goal. They are written to be played, not read:
seed the state, put yourself in the persona's head, and see whether the
screen answers the goal in the time the situation allows.

Every story has the same shape:

- **Persona** — who, and how much they trust or know the app.
- **Situation** — where they are, what else is on their mind, how much time
  and attention they have.
- **Goal** — hard (a train they must make, a time they must arrive by) or
  fuzzy (any reasonable train, sometime soon).
- **What happens** — the walk through the app as it is today.
- **Success looks like** — the observable outcome that would satisfy them.
- **Pressure points** — where the current design is likely to fail them, and
  the question a playtest must answer. These are hypotheses, not verdicts.

Stories are numbered in rough groups: 01–09 are commute moments, 10–19 are
setup, correction and environment, 20–28 are edge cases in people, data and
time. Add a story when a real complaint arrives; delete one when the app makes
it boring.
