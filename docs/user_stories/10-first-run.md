# First run

**Persona.** Dev, just installed the app on a friend's recommendation. Has
never seen it. Commutes Parramatta → Central.

**Situation.** Sunday evening on the couch, setting things up for Monday.
Relaxed, but will abandon the app if setup takes more than a minute or asks
for anything personal.

**Goal.** Fuzzy: "set it up so it just works tomorrow morning."

## What happens

1. The app opens on the `New trip` sheet with `From` focused.
2. Dev types `parr`. The hint says `Keep typing`, then `Searching…`, then the
   matches appear. Dev taps Parramatta.
3. Focus moves to `To`. Dev types `cent`, taps Central.
4. The save button reads `Save Parramatta → Central`. Dev taps it.
5. Home appears with the next Parramatta departure and one trip row.

## Success looks like

- Under a minute, no account, no permission prompt.
- The home screen makes sense with zero history: the header is the next
  train, the row says `SHOWN ABOVE`, and nothing claims to know Dev.

## Pressure points

- The lede says "Save one direction only. When today's ride is done, the
  way back is ready." Dev has no idea what "ride is done" means yet, and the
  promise is only true if Dev focuses a train (story 08).
- Pressing the keyboard's Search or Enter key does nothing. Many people hit
  it after typing; the top match should be picked.
- On Sunday evening the header shows Sunday's next train. If the corridor is
  on trackwork the very first screen may be empty or bus-only. What does
  first contact look like then?
- The header's figure slot reads `TIMETABLE ONLY` while the first board is
  still loading. Dev has not seen a timetable; the word describes nothing.
- The trip row's sub line says `SHOWN ABOVE` and nothing else, and every
  other row later says `NEVER RIDDEN`. Does the first row feel like a
  configured thing, or like a placeholder?
